*render-markdown-mermaid.txt*  Inline mermaid rendering for render-markdown.nvim

render-markdown-mermaid.nvim renders fenced |mermaid| code blocks inline with
|render-markdown.nvim| by calling `selkie` (default), Beautiful Mermaid (`bm`),
`termaid`, `mermaid-ascii`, or `merman-cli` (opt-in).
The default setup attaches to both Markdown and MDX buffers.

INSTALL

Use your plugin manager to install:

>
    {
        'cavanaug/render-markdown-mermaid.nvim',
        dependencies = {
            'nvim-treesitter/nvim-treesitter',
            'MeanderingProgrammer/render-markdown.nvim',
        },
        build = ':TSUpdate markdown markdown_inline',
        opts = {},
    }
<

This uses the plugin defaults and automatically configures
|render-markdown.nvim|.

HEALTH

Use:

>
    :checkhealth render-markdown-mermaid
<

This verifies that `render-markdown.nvim`, `selkie`, `bm`, `termaid`,
`mermaid-ascii`, and `merman-cli` are available, then reports which renderer
will be selected by default.
It also checks for the `markdown` and `markdown_inline` treesitter parsers.

Note that |render-markdown.nvim| may still warn about optional LaTeX support if
the `latex` parser or a converter such as `utftex` / `latex2text` is not
installed. Those warnings only matter if you want LaTeX rendering.

OPTIONS

The plugin exposes `require('render-markdown-mermaid').setup(opts)` and, when
using lazy.nvim, `opts = {}` maps directly to that setup table.

Default values: >
    {
        mode = 'unicode',
        placement = 'above',
        replace = false,
        cmd = { 'selkie' },
        width = nil,
        auto_setup_render_markdown = true,
        debounce = 150,
        timeout = 2000,
        cache = true,
        hide_source = false,
        max_block_lines = 200,
        max_preview_lines = '75%',
        center = true,
        focus_key = '<CR>',
        render_markdown = {
            file_types = { 'markdown', 'mdx', 'markdown.mdx' },
        },
        cli = {
            border_padding = 1,
            padding_x = 5,
            padding_y = 5,
        },
        ui = {
            pending = '󱎫 Mermaid rendering...',
            error = '󱂅 Mermaid render failed',
            report = '󰛈 Structured text report (not a diagram)',
            fallback = '󰛈 Diagram too wide; structured text fallback',
        },
    }
<

The default renderer selection prefers `selkie`, then `bm`, then `termaid`, and
falls back to `mermaid-ascii`. Set `cmd = { ... }` to override that choice
explicitly. When `mode = 'ascii'` is set, an ASCII-capable backend (`bm`, then
`termaid`, then `mermaid-ascii`) is preferred instead, since `selkie` always
renders with Unicode box-drawing characters.

`width` enables window-width fitting for renderers that support it (currently
`merman-cli`). `'auto'` uses the width of the window showing the buffer; a
number fixes the column budget. When `cmd` is `merman-cli`, `width` defaults to
`'auto'`: flowcharts and sequences retry a compact layout, and diagrams that
still exceed the width fall back to a structured text report. Structured text
output and fallback reports are prefixed with a notice line (`ui.report` /
`ui.fallback`), so they are distinguishable from diagrams. Set `width = false`
to opt out of width fitting while using `merman-cli`.

`render_markdown` is an optional passthrough table forwarded to
|render-markdown.nvim| when this plugin auto-configures it.

`placement` controls whether the rendered diagram is shown `above` or `below`
the raw mermaid fence while editing. The default is `above`.

If `replace = true`, the raw mermaid fence is visually replaced in normal mode
whenever the cursor is outside that block. Entering that block or entering
insert mode reveals the source again and falls back to `placement`.

`mode` controls whether text renderers use Unicode box-drawing characters
(`unicode`) or plain ASCII fallback characters (`ascii`). The default is
`unicode`.

If `hide_source = true`, the raw mermaid fence is concealed whenever the cursor
is outside the fence, while the rendered diagram stays visible.

SCROLLING TALL DIAGRAMS                                    *:MermaidFocus*

`max_preview_lines` bounds the inline diagram's height. The default, `'75%'`,
uses up to 75% of the window height and recalculates on resize. Percentage
strings (for example '50%' or '90%') must be greater than 0 and at most 100.
A few rows remain reserved for the header and source anchor. Existing positive
integers still set a fixed row budget, capped to fit the window. Set `false`
for unlimited inline output. Legacy 'auto' resolves to the '75%' default.
Small diagrams render unchanged, without a scrolling header.

`center = true` horizontally centers diagrams in the text area, excluding
number/sign columns. Padding uses the widest row of the full diagram and
remains constant across rows/pages. Focus keeps the same alignment without
adding spaces to copied text. Diagrams wider than the window stay left-aligned
for horizontal scrolling. Set `center = false` for original left alignment.

Place the cursor on a rendered Mermaid fence or its inline preview anchor,
then press Enter once. No command is required. `:MermaidFocus` is an optional
alternative.
A read-only scratch buffer overlays the inline preview, putting a real cursor
in the rendered output. The header shows the visible row range and total rows.
Normal Vim behavior applies, without remapping movement keys:

    h/j/k/l, w/b, f, counts         Cursor motions through rendered text
    Ctrl-d/u, Ctrl-f/b, wheel      Native scrolling
    gg / G                         First / last rendered line
    /, ?, n / N                    Native search
    Visual selection, y, yy        Select/copy rendered text
    Tab / Shift-Tab                 Next / previous installed renderer
    q / Esc (Normal mode)          Leave diagram focus
    :MermaidFocus                  Toggle back to the Markdown source

Only q/Esc and Tab/Shift-Tab are mapped in the scratch buffer; movement keys
are not remapped.
The source Enter shortcut opens navigation only on a rendered Mermaid block
or preview anchor. Elsewhere it delegates to the existing Enter mapping, or
to native Vim behavior when Enter was unmapped.
On exit, the original source cursor and window view are restored and the
scratch buffer is wiped. Switching buffers/windows, closing the viewer, or
editing/removing its source fence also releases focus. Navigation reuses
rendered output without invoking the CLI or modifying the Markdown source.
Wide output does not wrap; native horizontal scrolling works too. Small
diagrams can also be focused to select/copy their rendered text.

Diagram cursor and scroll positions are per fence, retained until the buffer
text changes. Inactive virtual lines are shared between source windows; the
viewport fits the smallest window. Resizing adjusts the viewport and keeps
it visible while focused. Report/fallback notices stay outside the scrolling
rows. Even with max_preview_lines = false, focus uses a screen-sized window.
The header uses the RenderMarkdownMermaidScroll highlight group.

`focus_key` changes the source-buffer shortcut (default: '<CR>'). Set it to
false to disable the shortcut and restore the original mapping. For example:
>lua
    opts = { focus_key = '<Tab>' }
<

SWITCHING RENDERERS                                         *:MermaidCycle*

While navigating a diagram, Tab cycles to the next installed renderer and
Shift-Tab cycles backwards. The same viewer keeps its previous output until
the new result is ready, then replaces it in place. Other inline previews
also retain their output while rendering. The header identifies the output
currently shown. Tab works while rendering; leaving the viewer prevents a
late result from reopening it. Tab in the source buffer is unchanged.

`:MermaidCycle` works from any buffer. Use `:MermaidCycle!` for the previous
renderer. The order is selkie, bm, termaid, mermaid-ascii, merman-cli, then
back to selkie; missing executables are skipped. Selection is session-wide
and refreshes loaded Markdown/MDX previews without changing saved config.
Only one installed renderer is a no-op; no renderers produces a warning.

Cached output is reused on return to a backend. Explicit cmd paths/wrappers
and width settings are retained. Merman enables automatic width fitting when
width was unset. Backend coverage still applies: unsupported diagrams show
an error, Selkie remains Unicode-only, and Merman can emit structured text.

Optional source-buffer shortcuts: >lua
    vim.keymap.set('n', '<leader>mc', '<Plug>(MermaidCycle)', {
        desc = 'Next Mermaid renderer',
    })
    vim.keymap.set('n', '<leader>mC', '<Plug>(MermaidCycleBack)', {
        desc = 'Previous Mermaid renderer',
    })
<
